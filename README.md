# مكتب العمليات وشئون الضباط

نظام محلي خفيف لإدارة الضباط والأفراد والراحات، مع أرشيف للفترات السابقة،
ويخزن كل البيانات في مجلد `data/` — ملف لكل يوم وملف واحد للقوة.

## التشغيل (Getting Started & Running)

### 🪟 1. على نظام ويندوز (Windows — 1-Click Zero Setup)

أسهل طريقة للتشغيل بدون أي إعدادات يدوية:
1. حمّل المشروع أو قم بعمل `git pull`.
2. اضغط مرتين (**Double Click**) على ملف: **`START_SYSTEM.bat`** (أو `run_windows.bat`).

> **ماذا يفعل الملف تلقائياً؟**
> - يفحص وجود Python ويقوم بتثبيته تلقائياً لو غير موجود عبر `winget`.
> - ينشئ البيئة الافتراضية `venv` ويفعلها.
> - يثبت كل المكتبات والاعتماديات المطلوبة (`requirements.txt`).
> - يشغل السيرفر ويفتح المتصفح تلقائياً على **`http://127.0.0.1:5000`**.

---

### 💻 2. التشغيل اليدوي عبر Terminal / CMD

#### على ويندوز (Windows CMD / PowerShell):
```cmd
# 1. إنشاء البيئة الافتراضية
python -m venv venv

# 2. تفعيل البيئة (في CMD)
venv\Scripts\activate.bat
# أو في PowerShell: .\venv\Scripts\Activate.ps1

# 3. تثبيت المكتبات
pip install -r requirements.txt

# 4. تشغيل النظام
python app.py
```

#### على لينكس / ماك (Linux / macOS):
```bash
# 1. إنشاء البيئة الافتراضية وتفعيلها
python3 -m venv venv
source venv/bin/activate

# 2. تثبيت المكتبات
pip install -r requirements.txt

# 3. تشغيل النظام
python3 app.py
```

ثم افتح المتصفح على الرابط: **`http://127.0.0.1:5000`**

---

### ⚙️ خيارات تشغيل إضافية

- **تغيير منفذ التشغيل (Port):**
  - في CMD: `set PORT=5050 && python app.py`
  - في PowerShell: `$env:PORT="5050"; python app.py`
  - في Linux/macOS: `PORT=5050 python app.py`

- **التشغيل الأطول استقراراً (سيرفر WSGI بـ Waitress):**
  - ثبّت `waitress` (`pip install waitress`) وشغّل: `python serve.py`

- **تشغيل الاختبارات الآلية (Testing):**
  - نفّذ الأمر: `pytest`


## الأقسام

قائمة جانبية على اليمين، مقسومة على ترتيب يوم الشغل نفسه — التشغيل اليومي
الأول (ده اللي بيتفتح كل يوم)، بعده سجلات القوة، وأخيرًا الراحات:

| المجموعة | الصفحة | المحتوى |
|---|---|---|
| — | **الرئيسية** | أعداد القوة، تنبيهات التقصيرة، مدخل مباشر لصفحات اليوم، القادم والمعلّق |
| **التشغيل اليومي** | اليومية التفصيلية | خدمات اليوم بأقسامها — **حفظ** حر، و**تأكيد** بيعتمد ويسجّل |
| | يومية الضباط | تشغيل الضباط اليومي + جدول الإجمالي |
| | اعداد الخدمات | الصباحية والمسائية + إجمالي الطوارئ |
| | سجل التغييرات | مين عدّل إيه وإمتى — بيتسجّل وقت التأكيد مش وقت الحفظ |
| **القوة** | بيانات الضباط | على القوة / الأرشيف — مرتبين بالرتبة دايمًا، مع نظام الراحة وحالة اليوم |
| | الأفراد | على القوة / الأرشيف — مع الدرجة والعمل والعنوان |
| | الفِرق والدورات | الدورات ومدة كل التحاق |
| | المأموريات | مأموريات لها دورة حياة (مخططة/بدأت/عادت/أغلقت) |
| | دفتر 43 | موقف كل ضابط يوم بيوم |
| **الراحات والإجازات** | سجل الراحات | كل فترات الراحة، مجمّعة بالنوع ثم بالرتبة |
| | الكشف الشهري | تاريخ راحة واحد لكل ضابط شهري أو نصف شهري |
| | الإحصائيات | رسوم بيانية وتفاصيل الراحات |

> **قيادة الإدارة** (مدير/وكيل الإدارة، طبي، بحث) إعدادات بتتغيّر مرة كل
> حركة ضباط، فمكانها مطوي تحت جدول الضباط في قسم «إعدادات القوة» — سطر
> الملخص بيقول مين شايل كل منصب من غير ما تفتحها، وبشارة ذهبية جنب اسمه
> في الجدول.

**أي قايمة ضباط في أي مكان في النظام مرتبة بالرتبة دايمًا** (عقيد، مقدم،
رائد، نقيب، ملازم أول...) — مش بالاسم أو التاريخ. **مدير الإدارة ووكيل
الإدارة دايمًا أعلى اتنين** في أي قايمة، بغض النظر عن رتبتهم العسكرية —
هما الأعلى تنظيميًا في الإدارة. التغيير بيسري فورًا لما تحدّث القيادة من
كرت «قيادة الإدارة».

## بنية الكود (Backend)

`app.py` بقى نقطة دخول رفيعة بس (بيعمل Flask app ويسجّل الـ blueprints).
كل المنطق اتقسّم جوا `backend/`:

| الملف | المسؤولية |
|---|---|
| `backend/constants.py` | كل الثوابت: التصنيفات، الرتب، أنواع الراحة... |
| `backend/store.py` | قراءة/كتابة مجلد `data/` (قفل + كتابة ذرية + كتابة اللي اتغيّر بس) وتوليد الأيدي التسلسلية |
| `backend/utils.py` | دوال عامة صغيرة (تحويل تاريخ، مفتاح الرتبة...) |
| `backend/people.py` | البحث عن شخص، ترتيب القوة، قواعد الراحة، مين كان على القوة يوم معيّن |
| `backend/leaves.py` | بناء سجل راحة والتحقق من التداخل |
| `backend/rest_suspension.py` | وقف الراحات: أوامر الوقف العام، وإيقاف راحة ضابط قبل نهايتها |
| `backend/duty.py` | جدول الإجمالي اليومي (`summarise`) |
| `backend/board.py` | اليومية التفصيلية — عرض محسوب على `day_assignments` نفسها اللي يومية الضباط بتقرا منها، فمفيش مزامنة منفصلة بين الاتنين |
| `backend/retro.py` | فحص التعديل بأثر رجعي على يوم مقفول (راحة/فرقة بتاريخ فات) — محتاج سبب مكتوب ويتسجّل في سجل التغييرات |
| `backend/rest_status.py` | حساب حالة الراحة/التقصيرة لكل ضابط (كانت في الجافاسكريبت) |
| `backend/routes/pages.py` | صفحات الـHTML — كل قسم له URL حقيقي |
| `backend/routes/*.py` | باقي نقاط الـ API، Blueprint لكل قسم (meta/people/leaves/duty/board/services) |
| `tests/` | اختبارات آلية (pytest) — شغّلها بـ `pytest tests/` بعد `pip install pytest` |
| `serve.py` | تشغيل اختياري بـ waitress بدل سيرفر التطوير (اختياري، للاستقرار الأطول) |

## بنية الواجهة (Frontend) — صفحات منفصلة

النظام كان كله **صفحة واحدة** والأقسام بتتخفي وتظهر بالجافاسكريبت، فأي
ريفرش كان بيرجّعك للرئيسية ويضيّع مكانك. دلوقتي كل قسم **صفحة مستقلة
بلينك حقيقي**:

`/` · `/officers` · `/personnel` · `/duty` · `/board` · `/catalog` · `/leaves`

يعني الريفرش بيفضّلك مكانك، وزراير الرجوع/التقدّم في المتصفح بتشتغل،
وتقدر تحفظ لينك لأي صفحة أو تفتحها في تبويب لوحدها.

| الملف | المسؤولية |
|---|---|
| `templates/base.html` | الهيكل المشترك: الشريط العلوي، القايمة الجانبية، ترويسة الصفحة، التوست |
| `templates/pages/*.html` | محتوى كل صفحة (`force.html` بيخدم الضباط والأفراد) |
| `templates/partials/*.html` | النوافذ — كل صفحة بتضمّ اللي بتستخدمه بس |
| `static/js/core.js` | المشترك: الشبكة، التواريخ، الرتب، توزيع النقرات |
| `static/js/<page>.js` | منطق كل صفحة لوحدها |
| `static/style.css` | نظام التصميم كله — الرموز (ألوان/مسافات/خطوط) وكل المكوّنات |

### نظام التصميم

`style.css` مقسوم لأقسام مرقّمة، وأوله كتلة `:root` فيها **كل** القيم:
الألوان، سُلّم المسافات (`--s1`…`--s8`)، سُلّم أحجام الخط (`--t-xs`…`--t-2xl`)،
وارتفاع موحّد للعناصر التفاعلية (`--control-h`). أي مكوّن جديد لازم ياخد
قيمه من هنا بدل أرقام مكتوبة على طول — ده اللي بيخلّي كل شريط أدوات في
النظام بنفس الارتفاع وكل جدول بنفس الكثافة.

- **الأزرار** كلها فروع من أساس واحد. `.primary` للفعل الأساسي في الصفحة،
  `.mini` للأفعال جوه الصفوف، `.mini.ok` / `.mini.bad` للتأكيد والخطر.
  الأسماء دي بيولّدها الجافاسكريبت، فمتغيّرهاش من غير ما تدوّر عليها.
- **العنصر المميّز** هو الخط الذهبي: تحت الشريط العلوي، جنب عنوان الصفحة،
  على ضلع القسم النشط في القايمة، وفوق كروت الرئيسية. مش زخرفة — هو اللي
  بيفصل المستويات عن بعض.
- **الأرقام** كلها `tabular-nums` عشان أعمدة الحصر تتصفّ زي الدفتر الورقي.
- **كل قائمة منسدلة قابلة للبحث**: `upgradeSelects()` في `core.js` بتحط حقل
  كتابة فوق كل `<select>` مفرد، والبحث بيستخدم نفس تطبيع العربي بتاع النظام
  («احمد» بتلاقي «أحمد»). **الـ`<select>` الأصلي بيفضل في الصفحة وهو مصدر
  الحقيقة** — كل `fillSelect()` و`$("#x").value` بتشتغل زي ما هي من غير أي
  تعديل، والحقل بيتزامن معاه عن طريق لفّ خاصية `value` ومراقب تغييرات.
  لو ولّدت `<select>` بعد تحميل الصفحة نادِ `upgradeSelects(container)` بعدها.
- **الاختيار المتعدد بقى صندوق وسوم**: `<select multiple>` كان صندوق تمرير
  بأربع أسطر جوّه 49 اسم، والاختيار فيه محتاج Ctrl+نقر — أي نقرة عادية بتمسح
  كل اللي قبلها. دلوقتي المختارين كلهم ظاهرين كشارات تتشال بنقرة (أو
  Backspace)، والقايمة بتفضل مفتوحة وانت بتختار. برضو الـ`<select>` هو مصدر
  الحقيقة — `readMulti()` بتقرا `selectedOptions` زي ما هي.
- الخطوط: كوفي للعناوين ونسخ/واجهة للمتن — الاتنين من خطوط النظام، مفيش
  أي تحميل خارجي (النظام بيشتغل أوفلاين).

### تحميل مخصوص لكل صفحة

كان في نداء واحد `/api/data` بيرجّع **225 كيلوبايت** (كل الضباط والأفراد
والراحات) في كل تحميل — حتى لو الصفحة محتاجة حاجة صغيرة منهم. دلوقتي كل
صفحة بتنادي `/api/bootstrap/<page>` وبتاخد شريحتها هي بس:

| الصفحة | قبل | بعد |
|---|---|---|
| الرئيسية | 225 KB | **2.2 KB** |
| الضباط | 225 KB | 20 KB |
| كتالوج الخدمات | 225 KB | 5 KB |
| يومية التشغيل / اللوحة | 225 KB | 10 KB |
| الأفراد | 225 KB | 54 KB |
| الراحات | 225 KB | 80 KB |

اللي وفّر ده:

- **كل صفحة بتاخد شريحتها بس** — صفحة الضباط مش بتحمّل الأفراد، والعكس.
- **حالة الراحة/التقصيرة بقت متحسبة في الباك إند** (`rest_status.py`)
  وبتوصل جاهزة مع كل ضابط، فالصفحة مش محتاجة تحمّل الـ248 سجل راحة عشان
  تعرض عمود «حالة اليوم». وده كمان شال ~150 سطر حساب تواريخ من
  الجافاسكريبت وخلّى منطق المدد في مكان واحد بدل اتنين.
- **الرئيسية أرقامها متحسبة على السيرفر** فبتحمّل ~2 كيلوبايت بس.
- **`ensure_ascii=False`** في `app.py` — Flask افتراضيًا بيهرّب كل حرف
  عربي لـ`\uXXXX` وده بيكبّر أي استجابة عربية لأكتر من الضعف على الفاضي.

التقسيم ده تنظيمي بس — مفيش أي تغيير في السلوك أو في شكل الـ API أو في
`data/`. `import_archive/` منفصل تمامًا (سكربتات استيراد لمرة واحدة من
ملفات الوورد، بتتشغّل يدوي ومش جزء من السيرفر) — ومكتوب فوق كل ملف فيها
تنبيه إن المسارات والسنة (2026) متثبّتة يدوي، فلازم تتعدّل لو الأرشيف اتنقل
أو استخدمتها لسنة جايه.

## شكل التخزين — مجلد مش ملف واحد

```
data/
  core.json                        القوة والأفراد والراحات والفرق والمأموريات
  days/2026/09/2026-09-05.json     تكليفات اليوم + حالات ضباطه + تأكيده + قفله
```

كان كله ملف واحد. تعديل خانة واحدة في اليومية كان بيقرا الملف كله ويسلسله
كله ويكتبه كله وياخد منه نسخة مضغوطة كاملة — أكتر من 2 ميجا شغل عشان تغيير
40 حرف، وبيزيد مع كل يوم شغل جديد (101 يوم كانوا 64% من الملف).

| | ملف واحد | مجلد |
|---|---|---|
| اللي بيتكتب في تعديل خانة | 2,133 كيلوبايت | **18 كيلوبايت** |
| دورة كاملة (قراءة + تعديل + حفظ) | 71 مللي ثانية | **44 مللي ثانية** |

**الشكل في الذاكرة ما اتغيّرش**: `store._read()` بيرجّع نفس الـdict بالظبط
(`data["day_assignments"][day]` وكده)، فمفيش مسار ولا مستودع ولا نموذج
اتغيّر عشان التقسيم. التقسيم تفصيلة تخزين مش شكل بيانات، وده اللي خلّى
التحويل ممكن من غير لمس أي منطق.

الملف اللي ما اتغيّرش **ما بيتلمسش** — المقارنة ببصمة sha256 للمحتوى
المسلسل، والبصمة بتتحسب مرة واحدة وقت قراءة الملف مش في كل طلب.

**النسخة الاحتياطية لسه ملف واحد مضغوط** فيه كل حاجة مجمّعة، عشان الاستعادة
تفضل «ارجع للحظة دي» مش «ركّب مية ملف». بس مابقتش بتتاخد مع كل كتابة (دي
كانت نص المشكلة): أي تغيير في `core.json` بياخد نسخة فورًا، وتغيير في
اليوميات بس بياخد نسخة كل دقيقتين على الأكثر.

## سلامة البيانات والتزامن

- كل تعديل (إضافة/تعديل/حذف) بيعدّي على `with_data()` في `backend/store.py`،
  اللي بتضمن إن التحميل والتعديل والحفظ يحصلوا كوحدة واحدة تحت نفس القفل —
  فمفيش احتمال إن طلبين في نفس اللحظة يمسحوا تعديل بعض من غير قصد.
- أي طلب فيه خطأ تحقق (validation) بيتلغى من غير ما يتحفظ أي حاجة في
  على القرص، حتى لو جزء من التعديل كان اتنفذ في الذاكرة قبل ما الخطأ يظهر.
- **سجل التدقيق**: كل تعديل ناجح بيتسجل سطر في `logs/audit.log` (التاريخ،
  نوع الطلب، والمسار، + اسم "من عدّل" لو مكتوب في حقل **اسمك** أعلى الشاشة).
  الحقل ده اختياري تمامًا ومفيش تسجيل دخول أو حسابات — مجرد توثيق بسيط لو
  احتجتوا تراجعوا مين لمس سجل معيّن وامتى. الملف بيدور تلقائيًا (5 ميجا × 5
  نسخ) عشان ما يكبرش من غير حد، ومش متتبّع في git (`logs/` في `.gitignore`).
- **النسخ الاحتياطي**: المشروع كله (الكود + `data/`) متتبّع بـ git محليًا.
  اعمل `git add -A && git commit -m "..."` بعد أي شغل يوم عشان يبقى عندك سجل
  كامل قابل للاسترجاع لأي نقطة زمنية (`git log`, `git diff`). الريبو محلي
  بالكامل ومفيهوش أي remote — مفيش حاجة بترفع لأي سيرفر خارجي.
- **الفرونت إند**: كل الأزرار المتولّدة ديناميكيًا (تعديل/حذف/إضافة) بتستخدم
  `data-action`/`data-id` + مستمع نقر واحد على مستوى الصفحة، بدل `onclick`
  مبني من نص حر مباشر. ده مهم لأن كل حقول النظام (اسم خدمة، تصنيف،
  ملاحظة...) حرة تمامًا حسب التصميم — أي نص فيه علامة اقتباس كان ممكن يكسر
  الصفحة أو ينفّذ كود لو فضل الأسلوب القديم.

## لوحة التشغيل المختصرة (صفحة المطابقة) — قابلة للتعديل بالكامل

تبويب داخل قسم «التشغيل» بيمثّل نفس فكرة ملف `D.docx` (اللي اسمه رقم اليوم
بس، زي `25.docx`) — منظّمة بالخدمة (مين شايل إيه) مش بالضابط — لكن هنا
**بيانات حرة قابلة للتعديل المباشر**، مش نص مشتق من يومية الضباط تلقائيًا.

### أول ما تفتح يوم قديم من الأرشيف (يونيو–أغسطس 2026)

بيتولّد له تلقائيًا وصف مبدئي مقسوم لخمس تصنيفات: **الخدمات الأساسية**،
**الأهداف** (بدون صباحية/ليلية — الهدف ثابت طول اليوم)، **الخدمات الطارئة**،
**أدوار بالإدارة** (ضابط عظيم/أمن الإدارة + أي
ضابط تشغيله "عمل" أو "عمل بالإدارة" بس، بيتحط باسم وظيفته الرسمية)،
و**المعسكر الفرعي** (نوبتجي المعسكر الفرعي، تصنيف مستقل). **الخدمات الطبية
مش موجودة هنا خالص** — محسوبة تلقائيًا في جدول الإجمالي بس.

ده بيحصل مرة واحدة بس أول ما تفتح اليوم. بعد كده بيبقى **بيانات مستقلة
تمامًا** قابلة للتعديل الحر، مالهاش أي علاقة بالنص الأصلي.

### التعديل الحر — «بمزاجك»

كل خانة (صف) في اللوحة عندها:

- **التصنيف** — اكتب أي اسم (مش لازم يكون من الأربعة الجاهزين). لو
  التصنيف جديد بيتحفظ تلقائي ويظهر تاني المرة الجاية.
- **اسم الخدمة** — حر تمامًا.
- **الفترة** — صباحية / ليلية / بدون.
- **الضابط** — اختياري. اختار من القوة أو اكتب أي اسم حر (لفرد مش في
  الروستر). سيبه فاضي يبقى الخانة شاغرة (محتاجة تكليف).
- **الاحتياجات** — قايمة مفتوحة تضيفها بنفسك: أي نوع (ضابط/فرد/مج/وحدة/أي
  حاجة) + العدد + ملاحظة حرة (زي "قتالية" أو "رياضي"). مفيش قايمة مقفولة.
- **ملاحظات** — نص حر.

بكده اليومية بقت بتغطي أي خدمة حتى لو مالهاش ضابط خالص (زي التراحيل)، وأي
حدث خاص (مباراة، خطة انتشار...) بيتعمل له قسم باسمه من «القسم على اللوحة».
الخدمة بتتعرض باسمها بس — «الاسم على اللوحة» و«الوسوم» اتشالوا من الخدمات
(`migrations/014_drop_board_label_and_tags.py` بتشيلهم من الأيام القديمة).

### حفظ ↔ تأكيد — خطوتين مش خطوة

في اللوحة زرارين مختلفين، وده مقصود:

| | بيعمل إيه | بيتسجّل في سجل التغييرات؟ |
|---|---|---|
| **حفظ** (جوه الخانة) | بيكتب في اليومية على طول، وبيظهر في كل العروض (يومية الضباط، دفتر ٤٣، اعداد الخدمات) | ❌ |
| **✔ تأكيد اليومية** (فوق) | بيعتمد الوضع الحالي ويسجّل الفرق عن آخر تأكيد | ✅ بلحظة الضغط |

المشغّل بيفضل يلعب في اليومية طول اليوم — يكتب اسم غلط ويصلّحه، يحط ضابط
ويشيله، يجرّب توزيعة ويرجع فيها. لو كل حفظ بيتسجّل، السجل بيمتلئ بمسوّدات
والتغيير الحقيقي بيضيع وسطها. التأكيد هو اللي بيقول «الصورة دي معتمدة».

السطر اللي بيطلع في السجل بيبقى جملة مقروءة، مش JSON خام:

```
١٦ سبتمبر ٢٠٢٦ 10:23   حركة ضابط/فرد   عقيد/ أحمد سمير:
                       كان «تدخل سريع ليل» ← بقى «امن المعسكر ليل»
```

- **الوقت المعروض = لحظة التأكيد**، وكل تغييرات نفس التأكيد بتحمل نفس
  اللحظة بالظبط.
- **التأكيد ينفع يتعمل أكتر من مرة في اليوم عادي** — وقبله بيظهر تأكيد
  «انت متأكد إنك عايز تأكد الخدمات الحالية؟». كل مرة بتسجّل اللي اتغيّر من
  آخر تأكيد بس، والتأكيد اللي مالوش فرق بيتسجّل كـ«إعادة تأكيد».
- **أول تأكيد** لليوم مالوش خط أساس يتقارن بيه، فبيتسجّل سطر واحد بعدد
  الخدمات بدل سطر لكل خدمة موجودة.
- الشارة جنب الزرار بتقول الحالة على طول: «لسه ما اتأكدتش» / «فيه تعديلات
  غير مؤكدة» / «مؤكدة 10:23 — فلان».

### ضباط الأهداف — مبدئيًا من تأكيد امبارح

أول ما يوم يتفتح (اللوحة أو يومية الضباط) وأهدافه لسه فاضية، بتتنسخ فيه
أهداف **آخر تأكيد لليوم اللي قبله** (`backend/target_defaults.py`). اللي في
راحة (منها الأسبوعية التلقائية) أو عنده حالة مكتوبة أو خارج القوة أو من «طبي»
بيتشال، وهدفه بيفضل شاغر. رأس القسم بيكتب «مبدئيًا من تأكيد يوم …» طول ما
محدش لمسها. لو اليوم اللي قبله اتأكد تاني والأهداف لسه زي ما اتنسخت، بتتحدّث
على التأكيد الجديد؛ أي تعديل بإيدك بيوقف التحديث ده خالص. البذر مابيتسجّلش
في سجل التغييرات، واليوم المقفول مابيتلمسش.

### أدوات اللوحة

- **ضباط «طبي»** (العيادة) مش بيظهروا في اللوحة خالص — لا في الأقسام المحسوبة
  ولا في اختيار التسكين. لسه بيتحسبوا في عمود «طبية» في يومية الضباط.
- **القسم على اللوحة** بيعرض كل الأقسام اللي اتعملت في أي يوم (الأحدث استخدامًا
  الأول)، وتقدر تكتب اسم جديد («＋ قسم جديد»). لما تختار قسم ليه خدمات في يوم
  قبل كده، بتظهر **آخر خدماته** وتختار منها اللي يتنسخ النهاردة — بالتفاصيل
  (اسم/فترة/تسليح/مجندين…) من غير الضباط والأفراد، والمكرر بيتخطّى.
- **تكرار** على أي خدمة بيفتح نافذة الإضافة متعبّية بنفس البيانات من غير الناس،
  والنسخة بتتحط تحت الأصلية.
- **ترتيب الخدمات جوّه القسم** (▲/▼ أو Ctrl+Alt+↑/↓، والبديل Alt+Shift+↑/↓) —
  ترتيب عرض بس (`pos`)؛ ترتيب التسجيل نفسه مابيتغيّرش، لأن «أول خدمة اتحط
  عليها» هي اللي بتحدد خانة الضابط في الإجمالي.
- **اختصارات** (زرار «⌨ اختصارات» أو `?`): ↑/↓ اختيار، Enter/E تعديل، D تكرار،
  Delete حذف، N إضافة، PageUp/PageDown يوم قبل/بعد، T النهاردة، Ctrl+Enter حفظ.
  بتشتغل على الكيبورد العربي كمان.

### الإجماليات في «اعداد الخدمات»

الورقة بتعرض الإجماليات في تلات أماكن، زي ورقة الإكسل الأصلية بالظبط:

1. **شريط فوق** — لمحة سريعة وإنت بتملا.
2. **سطر «الإجمالي» تحت كل بلوك** — «٢٥ خدمة / ٥٣ مجند».
3. **الإجمالي الكلي تحت خالص** — آخر حاجة في الصفحة، بالحبر الكحلي.

رقمين مختلفين في كل مكان: **عدد الخدمات** (صفوف) و**عدد المجندين** (مجموع
الأرقام) — الورقة القديمة كانت بتعرض الاتنين وسهل جدًا اللبس بينهم.

«الطوارئ» في شريط الإحصائيات رقم واحد (المتكررة + اليومي) زي الورقة، بينما
كل بلوك منهم له إجماليه تحته لوحده.

### بلوك الطوارئ في «اعداد الخدمات» — بيتقرا من اللوحة

قسم «الخدمات الطارئة» في اليومية التفصيلية هو مصدر بلوك الطوارئ في ورقة
اعداد الخدمات. **كل** خدمة مكتوبة هناك بتظهر في الورقة على طول — من غير
ما تستنى تأكيد ولا نسخ ولا إدخال تاني.

عدد المجندين بيتخزّن على صف الخدمة نفسه (`conscript_count`)، وينفع يتكتب
من المكانين: من خانة الخدمة على اللوحة، أو من الخانة اللي جنب الخدمة في
الورقة. الاتنين نفس الحقل، فمفيش نسختين للرقم ولا احتمال اختلاف.

جنب كل خدمة بيتعرض **القوام زي ما هو على اللوحة** («ضابط ×1، فرد ×2») —
ده تلميح للي بيكتب الرقم، و**مابيتجمعش في الإجمالي أبدًا**: حقل
`conscripts` معناه «وحدة / فرد / طلبة» مش «عدد مجندين»، «إزالة الأربعين»
مكتوب عليها [وحدة ٠، فرد ١] بينما ورقة الإكسل بتقول ٧.

> كان في فلتر بيخفي أي صف عدده صفر، فالخدمة اللي لسه ما اتكتبش عددها كانت
> **تختفي** من الورقة بدل ما تفكّر المشغّل إنها ناقصة. النتيجة كانت ورقة
> طوارئ فاضية في كل يوم من الـ101 يوم رغم إن فيهم 1257 خدمة طارئة. دلوقتي
> الصف بيبان بصفر ومتعلّم، والعدّاد فوق بيقول «كام خدمة لسه من غير عدد».

### قفل اليوم — بيحصل لوحده الساعة ١٢

اليوم اللي بيعدّي بيتقفل تلقائيًا، من غير أي مجدول ولا خدمة شغّالة في
الخلفية: اليوم بيتحسب مقفول لو تاريخه أقدم من تاريخ النهاردة، خلاص. ده
مقصود لأن الجهاز معزول وممكن يتقفل بالليل ويتفتح الصبح — أي مجدول كان
هيفوّت منتصف الليل والجهاز مطفي.

    يوم فات       -> مقفول تلقائيًا
    النهاردة      -> مفتوح (وفيه زرار «قفل اليوم بدري» لو خلصت)
    يوم جاي       -> مفتوح، عشان التجهيز المسبق

اليوم المقفول بيرفض أي كتابة من السيرفر نفسه (٤٠٩)، مش من الواجهة بس.
عشان تعدّل فيه لازم **فتح استثنائي بسبب مكتوب**، والفتح ده صالح **لليوم
اللي اتعمل فيه بس** وبعدين اليوم بيرجع يتقفل تلقائي — من غير القيد ده كان
الفتح الاستثنائي هيبقى فتح دائم، وساعتها القفل التلقائي مالوش أي معنى بعد
أول مرة حد يفتح فيها يوم قديم. القفل والفتح الاتنين بيتسجّلوا في سجل
التغييرات.

### الربط مع يومية التشغيل — في الاتجاهين

اللوحة ويومية التشغيل **مربوطين تلقائيًا**، فأي تكليف بيظهر في الاتنين
وجدول الإجمالي بيتحدّث على طول:

- **تحط ضابط على خدمة من اللوحة** → بيتشال من «عمل بالإدارة (الصافي)»
  وبيتحسب في خانته الصح في جدول الإجمالي.
- **تشيله (أو تشيل الخانة كلها)** → بيرجع صافي تاني.
- **تكلّفه من زرار «تكليف»** في يومية التشغيل → الخدمة بتظهر على اللوحة.
- **تشيل التكليف من اليومية** → الخانة بتفضل موجودة على اللوحة بس **شاغرة**
  (من غير ضابط)، لأن الخدمة نفسها لسه مطلوبة ومحتاجة بديل.

التصنيف (خارجية/داخلية/حراسات/طبية) بيتحدد **على الخانة نفسها** وقت
التكليف — مفيش كتالوج منفصل تتربط بيه الخدمة بـid أو بمطابقة اسم. لو
مش محدد تصنيف على الخانة، الضابط بيفضل محسوب صافي.

الأسماء اللي مش خدمات أصلًا — زي **مدير الإدارة**، **وكيل الإدارة**،
**قائد المعسكر الفرعي** — مقصود إنها ما تتربطش، والضابط بيفضل في الصافي
لأن دي مناصب إدارية مش خدمة في جدول الإجمالي.

> التقصيرة والانتداب والغياب ونص الملاحظة **مش بتتأثر بالمزامنة** — دي حالة
> الضابط نفسه، مش تكليف بخدمة.

## قيادة الإدارة (الهيكل التنظيمي)

في كرت **«قيادة الإدارة»** أعلى صفحة الضباط قسمين مختلفين:

- **مناصب فردية** (`COMMAND_ROLES` في `backend/constants.py`): **مدير
  الإدارة** و**وكيل الإدارة** — منصب واحد، ضابط واحد شايله، قايمة منسدلة
  عادية (`PATCH /api/command`).
- **مناصب جماعية** (`GROUP_ROLES`): **طبي** و**بحث** — أكتر من ضابط ممكن
  يشيلوا نفس المنصب في نفس الوقت، فالاختيار قايمة اختيار متعدد (چيك بوكس)
  مش قايمة منسدلة، ومعاها زرار «حفظ» مستقل (`PATCH /api/command-groups`
  بقايمة معرّفات كاملة بتستبدل الأعضاء الحاليين، مش إضافة تراكمية).

الأربعة بيتغيّروا مع حركة الضباط، وكل واحد بيظهر جنب اسم صاحبه في الجدول
بشارة ذهبية.

**مدير/وكيل الإدارة بس** هم اللي بيتقدّموا في ترتيب أي قايمة ضباط (أعلى
اتنين بغض النظر عن الرتبة العسكرية)؛ منصبي «طبي» و«بحث» مالهمش أي أثر
على الترتيب، هما مجرد تسمية.

**التغيير بيسري فورًا** لما تحدّث القيادة من الكرت — مفيش تشغيل تلقائي
في «أدوار بالإدارة» ليوم جديد؛ زي أي ضابط تاني، لازم تكلّفه بإيدك من
اللوحة أو يومية التشغيل لو حبيت خدمته تظهر في القسم ده (ما عدا «طبي»،
شوف تحت).

اليوم اللي اتحفظ بالفعل مابيتغيّرش بأثر رجعي في «أدوار بالإدارة»: لو
غيّرت المدير النهاردة، الأيام القديمة بتفضل زي ما هي فيه، والتغيير بيسري
على الأيام الجديدة بس. ولو حذفت خانة القيادة من يوم معيّن مش هترجع تاني
في اليوم ده.

## الخدمات الطبية — عمود «طبية»

عمود «الخدمات الطبية» (موجود/راحة) في جدول الإجمالي بيتحدد من مصدرين
(`backend/duty.py`)، أي واحد فيهم كافي:

1. **عضو في منصب «طبي»** الجماعي في قيادة الإدارة — أكتر من ضابط ممكن
   يكونوا أعضاء في نفس الوقت (عكس مدير/وكيل الإدارة)، بيتغيّروا من كرت
   «قيادة الإدارة» مش يوم بيوم.
2. **خدمة تصنيفها «طبية»** من كتالوج التصنيفات (`SERVICE_KINDS`) معيّنة
   على أي ضابط اليوم ده — لو حد تاني غطّى العيادة يوم بعينه بره الأعضاء
   الأصليين.

زي مدير/وكيل الإدارة بالظبط، تغيير أعضاء منصب «طبي» بيسري على **كل
الأيام** (القديمة والجديدة) لأن العمود ده عرض محسوب مش تكليف مخزّن. قبل
كده كان فيه تحديد يدوي لليوم بالذات (شيك بوكس «طبية» في مودال تكليف
الضابط) وفحص نص حر على منصب الضابط (`MEDICAL_POSTS`) — الاتنين اتشالوا
لصالح المنصب الموحّد ده.

لو الضابط في راحة وهو محسوب طبية، بيتحسب "طبية: راحة" مش "خوارج: راحة" —
زي ما هو معمول بيه في الوورد. تكليف صريح تاني (حالة مكتوبة زي انتداب/
غياب) بيغلب الطبية زي أي ضابط عادي.

## نظام التفتيشات الأسبوعي

تفتيشات تأمين المجندين لزيارات أهالي المساجين — بتتكرر بنفس الأسماء كل
أسبوع على أيام ثابتة (مثلًا «تفتيش فيصل» كل سبت وأحد واثنين). الجدول
الأسبوعي (اسم كل تفتيش + تسليحه + عدد مجنديه) بيتحرّر من سكشن **«نظام
التفتيشات»** جوّه صفحة **دليل الخدمات** (`backend/inspection_schedule.py`,
`PATCH /api/inspection-schedule/<يوم>`).

أول ما يوم من أيام الأسبوع ده يتفتح لأول مرة في اليومية التفصيلية،
تفتيشاته بتتحط عليه تلقائيًا في قسم مخصّص اسمه **«تفتيشات»** — قوامها
مجندين بس (من غير ضابط)، بتسليحها وعددها المحدّدين في الجدول. بعد كده
هي خانات عادية زي أي خانة تانية: تتعدّل، تتكلّف عليها أفراد، أو تتشال
بحرية من غير أي علاقة بالجدول الأسبوعي تاني — وحتى لو اتشالت كلها،
اليوم ده مايترجعش يتحط عليه نفس التفتيشات تاني (علامة مستقلة في
`inspection_seeded_days`، مش وجود خانات فعلية).

تغيير الجدول الأسبوعي (إضافة/تعديل/حذف تفتيش) بيسري على أي يوم لسه ما
اتفتحش بس — الأيام اللي اتفتحت وتحطّت عليها تفتيشات قبل كده تفضل زي ما
هي، زي مبدأ قيادة الإدارة بالظبط.

## دليل الخدمات — فلترة

صفحة **دليل الخدمات** فيها شريط فلاتر فوق الشبكة: بحث حر بالاسم أو
التعليمات، وتصنيف، وفترة، ووسم — الأربعة بتتطبّق مع بعض. الوسوم نفسها
(`service_tags`) بتتسجّل تلقائيًا أول ما تُكتب على أي خدمة في الدليل (حقل «الوسوم»
في مودال خدمة الدليل)، فقايمة فلتر الوسوم بتكبر لوحدها مع الاستخدام من غير
أي إعداد مسبق.

### الراحات / التقصيرات / الخوارج / عمل بالإدارة

دول لسه محسوبين تلقائيًا من حالة الضابط (نظام الراحة، الإجازات، التقصيرة)
— مش جزء من التعديل الحر، لأنهم مرتبطين بسجل الضابط نفسه مش بخدمة معيّنة.
عمود الراحات بيوضح **من يوم، إلى يوم، والعودة يوم** — مش تاريخ واحد بس.

### زرار «بكرة» — تسليم واستلام

جمب زرار «النهاردة» — بينقلك ليوم بكرة، ولو فيه ضباط تقصيرتهم النهاردة
(يعني راحتهم بتبدأ بكرة)، بيطلع تنبيه فوق اللوحة بيوضح كل واحد فيهم وكان
شايل إيه النهاردة، عشان تكلّف بديل بسهولة. التنبيه للعرض بس — مش بينسخ
التكليفات تلقائي (كتير من الخدمات، خصوصًا الأدوار بالإدارة، بتتغيّر يوميًا).

## التشغيل اليومي

بيعيد إنتاج **جدول الإجمالي** اللي تحت يومية الضباط بنفس شكله:

```
أصل القوة | الخدمات الخارجية | الخدمات الداخلية | الخدمات الطبية | الخوارج | الحراسات المشددة | الصافي
             صباحية/ليلية/بحث    صباحية/ليلية      موجود/راحة     تقصيرة، راحة، طارئة،
                                                                  غياب، مرضي، فرقة، انتداب
```

**كل ضابط بيتحسب في خانة واحدة بس**، بالأولوية دي (زي اليومية الورقية):

1. الخدمات الطبية (بتتحدد من أعضاء منصب «طبي» أو خدمة تصنيفها «طبية»)
2. راحة / إجازة → الخانة المناسبة في الخوارج
3. انتداب خارج الإدارة أو غياب
4. **تقصيرة** — بتغلب الخدمة: الضابط اشتغل وخرج بدري فبيتحسب تقصيرة مش خدمة
5. الحراسات المشددة (عمل بهدف أو مشرف الأهداف)
6. خدمة داخلية (صباحية/ليلية)
7. خدمة خارجية (صباحية/ليلية)، والبحث في خانة مستقلة
8. الباقي → **الصافي**

الصافي بيتحسب تلقائي كباقي الطرح، والنظام بيوضح فوق لو المجموع مش مساوي
لأصل القوة.

### قوة اليوم مش القوة الحالية

لما تفتح يومية ليوم قديم، بيظهر **الضباط اللي كانوا على القوة في اليوم ده**
(انضمّوا قبله وما خرجوش لسه) — مش الضباط الحاليين. اللي خرج بعد كده بيبان
بعلامة «خرج يوم كذا». اتظبط على الـ92 يوم: قوة اليوم طابقت اليومية الأصلية
في 90 يوم من 92.

### تصنيف الخدمة

تصنيف الخدمة (خارجية / داخلية / حراسات / طبية) بيتحدد **على كل خانة
تكليف لوحدها** وقت الحفظ — مفيش كتالوج مركزي يربط اسم الخدمة بتصنيف
ثابت. تعديل التصنيف على خانة معيّنة بيأثر على اليوم ده بس. «دليل
الخدمات» (`/service-catalog`) توثيق مرجعي (الفترة، القوام المطلوب،
التعليمات) — مش مرتبط بحساب جدول الإجمالي.

## الراحات

- **نظام الراحة** لكل ضابط: `أسبوعية` (مع تحديد اليوم) أو `نصف شهرية` أو `شهرية` أو `—`.
  ده الاستحقاق الثابت، وبيتعدّل من زرار **تعديل** على الضابط.
- **فترة الراحة** (من تاريخ / لتاريخ) بتتسجل من زرار **راحة** على الضابط، أو من
  قسم الراحات بزرار **تسجيل راحة**. تاريخ العودة بيتحسب تلقائيًا = آخر يوم راحة + 1.
- النظام بيرفض أي فترتين متداخلتين لنفس الشخص، وبيرفض تاريخ نهاية قبل البداية.
- عمود **حالة اليوم** في جدول الضباط بيوضح: في راحة / تقصيرة / راحة قادمة / بالعمل.
- سجل الراحات مقسوم **بالنوع** بالترتيب ده: أسبوعية، نصف شهرية، شهرية، وبعدهم
  باقي الأنواع (مصيف، طارئة، مرضي...) — وجوّه كل نوع الضباط مرتبين بالرتبة.

### المدة القياسية

أول ما تحدد يوم بداية الراحة، تاريخ النهاية بيتحسب تلقائي حسب النوع:

| النوع | المدة |
|---|---|
| شهرية | 7 أيام |
| نصف شهرية | 3 أيام |
| أسبوعية | يوم واحد |

تقدر تعدّل تاريخ النهاية يدوي، والنظام بس هينبهك إن المدة مش قياسية.
المدد دي متعرّفة في `REST_DURATIONS` في `backend/constants.py`.

### تنبيه التقصيرة

**اليوم اللي قبل الراحة بيكون تقصيرة** للضابط بعد خدمته. النظام بيحسبها لكل
أنواع الراحات (شهرية / نصف شهرية / أسبوعية) وبيطلّع **تنبيه قبلها بيوم**.

> مثال: ضابط راحته يوم 5 → يوم 4 تقصيرة → التنبيه بيبدأ يظهر من يوم 3.

- بالنسبة للراحة **الأسبوعية** النظام بيحسب أقرب يوم راحة جاي من نفسه (من `rest_day`)
  حتى لو مفيش فترة مسجلة، وبيطلّع التقصيرة على أساسه.
- التنبيه بيظهر في **شريط برتقالي فوق** في قسم الضباط، وفي **بادچ في الشريط العلوي**،
  وكمان كشارة في عمود «حالة اليوم».
- مدة التنبيه بتتظبط من `TAQSEERA_NOTICE_DAYS` في `backend/constants.py` (افتراضي: يوم واحد قبل التقصيرة).

### الراحة الأسبوعية — بتتسكّن لوحدها

أول ما يوم مفتوح يتفتح (اللوحة أو يومية الضباط)، كل ضابط نظامه أسبوعي ويوم
راحته هو اليوم ده بتتسجّل له راحة يوم واحد (`backend/weekly_rest.py`، علامة
«تلقائية») وبتظهر في «الراحات» على اللوحة. بيتخطّى اللي عنده راحة تانية أو
فرقة اليوم ده، ومفيش تسجيل خالص وقت وقف الراحات الأسبوعية. اليوم بيتسكّن
**مرة واحدة**: لو مسحت الراحة (الضابط هيشتغل)، مش هترجع تاني.

في «الكشف الشهري» جزء **الراحات الأسبوعية**: كل ضابط أسبوعي بيومه الثابت
وموعده الجاي وراحاته القادمة، وزرار **«＋ راحة إضافية»** لتاريخ جاي — راحة
يوم زيادة (علامة «إضافية») من غير ما يوم راحته الثابت يتغيّر ولا راحة
الأسبوع العادية تتلغي.

### وقف الراحات

للضباط بس (الأفراد مش داخلين). ليه صفحة لوحده **«وقف الراحات»** في القايمة
تحت الراحات والإجازات (`/leaves/suspension`، `backend/rest_suspension.py`)، وعليها
شارة حمرا «موقوفة» من أي صفحة طول ما فيه أمر ساري. الصفحة بتعرض كل أمر ساري
ومعاه **بالظبط** الراحات اللي أوقفها أو لغاها، والأوامر اللي اتفتحت قبل كده.

**أمر وقف عام** — على خطوتين: (١) بتختار أنواع الراحة اللي تتوقف من كل
الأنواع الموجودة (`LEAVE_TYPES`، فأي نوع جديد بيظهر لوحده) وتكتب السبب، (٢)
قدامك بتظهر راحات الضباط **الجارية والقادمة** من الأنواع دي، من غير أي تحديد —
**إنت** اللي بتختار منها اللي تتوقف، وعدّاد فوق القايمة بيقولك قبل التنفيذ
كام هتتوقف وكام هتتلغي وكام هتفضل زي ما هي.

- الأمر بيفضل ساري لحد ما تضغط **«فتح الراحات»** — مالوش تاريخ نهاية.
- وهو ساري، **تسجيل راحة جديدة** من نوع موقوف لأي ضابط **بيترفض** (نموذج
  الراحة، التعديل، وكشف الراحات الشهرية). تعديل راحة موجودة بيترفض بس لو بيطوّلها
  أو بيحوّلها لنوع موقوف — التقصير أو تعديل الملاحظة مسموح.
- الراحة **الأسبوعية المحسوبة** (من `rest_day` من غير سجل) بتقف لوحدها:
  مفيش تنبيه تقصيرة، ولا تنبيه «راحة أسبوعية غير مسجلة».
- كشف الراحات الشهرية بيعرض الضابط **«موقوفة»** بدل «محتاج تاريخ جديد».
- **اليومية التفصيلية ويومية الضباط** فيهم شريط أحمر في أي يوم الوقف ساري
  فيه، وبيعرض الضباط اللي **رجعوا للعمل في اليوم ده بإيقاف راحتهم** — دول
  اللي محتاجين يتسكّنوا، فبيبانوا في مكان التسكين نفسه.
- **فتح الراحات مابيرجّعش أي راحة اتوقفت** — الضباط بعدها بيتسكّنوا في راحة
  من جديد عادي. **الاستثناء:** لو الفتح في **نفس يوم الوقف**، مودال الفتح بيعرض
  اختيار «رجّع الراحات زي ما كانت» — الراحات اللي اتوقفت بترجع لنهايتها الأصلية
  واللي اتلغت بتتسجّل تاني بنفس رقمها. لو راحة تانية اتسجّلت في الأيام اللي
  اتفضّت، الفتح كله بيترفض ومفيش حاجة بتتغيّر.
- نوع الراحة الواحد مايتحطش في أمرين ساريين في نفس الوقت، فالفتح بيفتح بالظبط
  الأنواع اللي في الأمر ده.

**إيقاف راحة ضابط واحد** — زرار **«إيقاف»** على صف الراحة، أو **«إيقاف
الراحة»** جنب الضابط في صفحة الضباط لو هو في راحة دلوقتي، أو من مودال
**«الحالة»** في يومية الضباط:

- التاريخ اللي بتحدده هو **أول يوم رجوع للعمل**: الراحة بتتقص لحد اليوم اللي
  قبله. راحة لسه ما بدأتش بتتلغي بالكامل.
- السبب **إجباري** دايمًا — مش بس لو التعديل بيمس يوم مقفول.
- التاريخ الأصلي بيفضل محفوظ على السجل (`original_end` + `stopped_on` +
  `stop_reason`) وبيظهر في جدول الراحات كـ«موقوفة — كانت لحد …»، بدل ما
  يتكتب فوقه في صمت زي التعديل العادي. تواريخ الراحة الموقوفة بتتقفل بعد كده.
- الإيقاف مابيغيّرش منطق التسكين نفسه (الراحة أصلًا مابتمنعش التسكين) — الضابط
  ببساطة بيرجع للقوة: بيظهر في بحث التسكين، ومابيتحسبش في الخوارج.
- كل إيقاف/إلغاء/أمر/فتح بيتسجّل في **سجل التغييرات** بالسبب.

## البيانات

- الموجودون حاليًا في `active`، ومن خرجوا في `archive`، والراحات في `leaves`.
- رقم الأقدمية هو `code`. الأفراد ماعندهمش رقم أقدمية في المصدر فاتولّدلهم كود `ف-001`.
- عند إخراج شخص، لا يتم حذفه؛ يتم نقل سجله للأرشيف مع تاريخ الخروج والسبب.
- من الأرشيف تقدر **تسترجع** الشخص للقوة (بتاريخ انضمام جديد) أو **تحذف** السجل نهائيًا.
- تعديل اسم شخص بيحدّث اسمه في سجلات الراحات المرتبطة بيه تلقائيًا.
- النسخ الاحتياطي عبر git — شوف قسم «سلامة البيانات والتزامن» فوق.

## ملاحظة

هذا الإصدار مخصص للاستخدام المحلي على جهاز واحد. **لا توجد فيه حسابات
مستخدمين أو صلاحيات دخول عمدًا** — ده مناسب طالما السيستم شغّال على
`127.0.0.1` (الإعداد الافتراضي في `app.py`) ومحدش وصله غير جهاز واحد.

**لو قررتوا يومًا تشغّلوه على الشبكة (`host="0.0.0.0"`) عشان أكتر من جهاز
يوصله، لازم تضيفوا مصادقة الأول** (أبسط حل يناسب مكتب واحد: HTTP Basic Auth
بكلمة سر مشتركة عبر `before_request` في `app.py`) — من غيرها أي حد على نفس
الشبكة هيقدر يشوف ويعدّل كل بيانات الضباط الشخصية (الأسماء، الهواتف،
العناوين) والتشكيلات اليومية من غير أي مانع.
